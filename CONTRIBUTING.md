# Contributing

Welcome! Useful contributions include a reproducible bug report, a clearer
example, documentation, translations, board testing and code.

## Choose the right place

Use community Discussions for questions, ideas, introductions and project
showcases. Report a confirmed defect in the affected project's issue tracker.
If you are unsure which project owns it, ask in community Discussions first.

## Propose a change

1. For a substantial change, discuss the problem and approach first.
2. Create a branch for one task. Keep unrelated changes out of the pull request.
3. Explain the problem, the resulting behaviour and how you checked it.
4. Include relevant tests or reproduction steps. State what was not tested.
5. Preserve upstream attribution and third-party licence notices. Contribute
   only material you have the right to share.

Use English for code, commit messages and reference documentation. Keep
translations beside the reference and mark machine-generated drafts for review.
Never include credentials, private keys, saved device sessions, customer data
or site-specific network configuration.

## Compatibility and hardware

Name the editor, SDK and firmware versions involved. For hardware, include the
exact board and revision, ESP-IDF/toolchain version and relevant wiring.
Separate simulator checks, on-board software checks and electrical I/O tests.
Use a local simulator or an isolated test bench for reproductions.

## Review

A pull request is reviewed for correctness, scope, compatibility, licence
provenance and relevant validation. Passing CI is evidence, not a substitute for
review. Maintainers may request a smaller change or more reproduction details.
