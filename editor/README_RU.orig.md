# MCS Sedona Web Lab 0.2 — 10.11.2026

Работающий локальный прототип отдельного Java-сервера и React-интерфейса. Обычная Java-библиотека Sedona/DASP/SOX, без зависимостей от MCS/Baja и без Node в работающем сервере. Node требуется только для сборки интерфейса и браузерных проверок.

## Новое в 0.2

Кнопка «Проект» открывает локальный редактор React Flow. Можно создать пустой проект, добавить реальные типы из палитры, соединить совместимые порты, изменить числовое/Boolean поле, переименовать блок и переместить его. Удаление блока удаляет его связи. История undo/redo — до 50 изменений, клавиши Ctrl+Z / Ctrl+Y / Delete вне полей ввода. Выход из режима редактирования сохраняет черновик и историю в памяти; несохранённые изменения защищены предупреждением при замене/закрытии страницы.

В палитре девять настоящих типов из devkit: ConstFloat, ConstBool, Add2, Mul2, Sub2, Div2, And2, Or2, Not. tools/ExportCatalog.java выгрузил разрешённые типы и унаследованные ID слотов из Java Schema с точными checksum kits. Значения новых блоков — defaults и введённые литералы; алгоритмы блоков в браузере не исполняются. X6 оставлен для просмотра/сравнения, редактирование ведётся в React Flow.

«Сохранить проект» выгружает JSON через обычное скачивание браузера. «Открыть JSON» проверяет версию формата, ID, координаты, типы связей и ограничения размера до замены текущей схемы. Файл содержит только явную модель: блоки, порты, координаты, связи, значения и метаданные происхождения. Пароли подключения/consumer tokens не экспортируются. Это наш формат mcs-sedona-project v1, не SAX/SAB и не готовая программа для прошивки. Сохранение на сервер и автосохранение пока не включены.

Связи: только одинаковые типы, один источник на вход, readonly/meta не принимают новые связи, дубликаты отклоняются; обратная связь разрешена. Импорт существующих схем допускает readonly-цели для просмотра, но не создаёт новые такие связи. Формат не подтверждает совместимость алгоритмов, native ABI или наличие всех kits на устройстве.

## Отдельная запись одного параметра

Обычный Start.cmd / Start.ps1 оставляет запись выключенной. Для явной стендовой проверки после остановки сервиса можно запустить Start.ps1 -EnableWrites. Это глобальная настройка данного локального процесса, не авторизация пользователей для удалённой работы.

В онлайн-режиме выбрать блок → «Сигналы» → параметр → «Прочитать и подготовить». Сервер показывает фактически прочитанное старое и желаемое значение. Пока не нажато «Подтвердить запись параметра», ничего не записывается. План действует 30 секунд и привязан к lease наблюдателя; другой наблюдатель не может его подтвердить. Отмена отзывает token. Перед записью повторно проверяются schema parts, имя/тип/родитель компонента и старое значение; при расхождении запись отклоняется. После write выполняется отдельный readProp, результат показывается в интерфейсе. Token одноразовый; OFF/reconnect сбрасывает подготовку.

Поддержаны только скалярные числовые/Boolean свойства с проверкой диапазона примитива; readonly, системное meta, credential-поля, actions и прочие типы запрещены. Это оптимистическая проверка, не атомарный compare-and-swap контроллера: внешняя запись всё ещё возможна между проверкой и write. При потере ответа token автоматически не повторяется, нужно перечитать состояние. Runtime-параметр не сохраняется в app.sab автоматически. Загрузка структуры локального проекта на устройство и прошивка ещё не реализованы.

Проверено на отдельном native SVM, не на .184: подготовка не пишет, конфликт с независимым SOX-клиентом блокирует commit, readback совпадает с независимым чтением, replay/чужой lease/readonly/NaN/отменённый token отклоняются. Пройден UI-путь подготовки, отмены и подтверждения; тестовое значение восстановлено. Логи: evidence/property-write.json, evidence/editor-browser.json, evidence/project-unit-test.log; снимки: project-editor.png, write-preview.png, write-verified.png. После тестов сервер возвращён к обычному запуску с записью OFF.

## Запуск

Требуется Java 17 или новее в PATH. Готовые классы и web/dist уже собраны. Start.cmd запускает отдельный сервер и открывает браузер. Адрес http://127.0.0.1:8098. Start.ps1 делает то же без открытия браузера; Stop.ps1 отключает SOX и останавливает только записанный процесс этого проекта с проверкой PID и командной строки. Рабочий MCS не меняется.

Прототип слушает только loopback. Удалённый доступ, вход пользователей, TLS и промышленное разграничение прав ещё не реализованы; это не готовый сервер для публикации в сети.

## Что работает

- Переключение React Flow 12.12.1 / AntV X6 3.1.8; одинаковые синтетические схемы на 100, 500 и 1000 блоков, по восемь полей в каждом, прямые и обратные связи. В режиме проекта React Flow поддерживает редактирование.
- Дополнительная библиотека холста загружается только при выборе. Демо значений включается отдельно, к контроллеру не обращается.
- Явное подключение к одному выбранному устройству по Java/SOX: чтение дерева, типов, свойств и связей. Отсутствующие манифесты запрашиваются через m:m.zip, legacy m/m.zip, затем отдельные XML; общий локальный ManifestDb. Проверка заявленных kit parts, не криптографическая проверка XML.
- Режим SNAPSHOT читает схему и закрывает транспорт; LIVE оставляет сессию. Нет автоподключения/автопереподключения, архивирования, компиляции и периодического полного перечитывания устройства.
- До восьми наблюдателей одного устройства. Одна SOX-сессия, объединение интересов, подписки на runtime видимых блоков и выбранного компонента инспектора, максимум 128 компонентов на наблюдателя. Отдельные поля не означают отдельные SOX-подписки — протокол группирует данные по компонентам.
- Серверные leases: heartbeat раз в 2 секунды, срок 8 секунд, уборка раз в секунду. Если браузер погиб и больше наблюдателей нет, сессия закрывается. Скрытая вкладка отправляет пустой интерес; при жёстком ограничении браузерных таймеров может потерять lease и потребовать ручного подключения.
- Сервер отправляет изменения кэша через SSE примерно раз в секунду; это не ограничитель частоты COV на устройстве. Снижение нагрузки устройства достигается снятием подписок/закрытием сессии. SSE включает только объединение интересов; ранее прочитанные значения остальных блоков остаются снимком и могут быть устаревшими.
- Явная кнопка OFF закрывает все viewer leases и SOX/UDP. Страница «Нагрузка» показывает режим, подписки, события COV и счётчики DASP. Она не измеряет CPU контроллера.

В этом прототипе нет загрузки структуры программы, прошивки, компилятора и архиватора. Параметры устройства пишутся только через отдельно разрешённую процедуру выше. Пароль подключения не записывается в конфигурацию/журнал; свойства с именами cred/password/secret/key исключаются из выдаваемой модели. Это ограниченный фильтр, а не полноценная классификация конфиденциальности всех vendor kits.

## Проверки и сохранённые доказательства

evidence/integration.json: настоящий локальный native SVM с пятью kits и types::ConstFloat, независимый UDP relay. Проверены пустой кэш манифестов, дедупликация двух подписчиков, частичная отписка, пустой интерес, OFF, смерть browser lease, отсутствие переподключения, SNAPSHOT и отклонение cross-origin POST. Дополнительно Playwright открывает реальную схему fixture в React, получает SSE и выключает обмен. Это тест локального SVM, не проверка 192.0.2.10 и не физического контроллера.

evidence/browser-benchmark.json: проверено наличие всех 100/500/1000 блоков, обновление 100 блоков и очистка подписчиков при смене движка. Один проход на headless Chromium, один ПК; значения updateDoubleRafMs включают ожидание кадров и не равны чистому CPU времени. Маршрутизация простая orth/smoothstep без обхода препятствий. Не является универсальным рейтингом библиотек и не заменяет тестов больших vendor-схем. Начальные результаты дают преимущество текущей реализации React Flow; она выбрана по умолчанию. Снимки синтетических схем явно помечены, native-sox-browser.png получен с настоящего локального тестового SVM.

Промежуточные версии: checkpoints. Сборка: npm ci --prefix web; npm run build --prefix web; python tools/build_server.py. Тесты: tests/LeaseTest.java; node tests/browser.mjs; python tests/integration.py. Для последнего нужен локальный Sedona devkit и native svm.exe из F:/Sedona/sedonadev-master; запускать только при свободных тестовых UDP-портах 12986 и 12987. Приватные ключи и MCS-лицензии в проект не копировались.

## Ограничения архитектуры следующего этапа

Пока одна выбранная SOX-сессия на процесс. Для нескольких устройств — registry отдельных DeviceGateway, общая блокировка Schema/ManifestDb, отдельные очереди и лимиты на устройство. В текущей библиотеке есть глобальные кэши и Env.home, поэтому разные home внутри одной JVM не переключаются. Компилятор следует вынести в отдельный процесс; известная совместимость refSize=8 требует самостоятельного подтверждения.

Следующий этап — преобразование проекта в совместимые SAX/SAB, проверка установленной схемы и применение структурных изменений с резервной копией. Права пользователей и удалённый доступ нужны до сетевого выпуска. Фоновые сервисы включаются только по явной настройке; безопасное прекращение уже начатой прошивки должно проектироваться отдельно.
# Совместимость DASP

Версия 0.3.7: дублирование онлайн и восстановление потока.

- Правый клик → «Дублировать на устройстве» или Ctrl+D в онлайн-режиме:
  создаёт один компонент того же точного типа в той же папке, копирует его
  config-параметры свежим SOX-чтением, назначает blkN и сдвигает позицию на 3
  клетки. Ссылки и дочерние компоненты не копируются, runtime-состояние запускается
  заново. Поддеревья и компоненты с учётными данными этим действием не дублируются.
  Значения config проверяются обратно, затем/при создании вызывается App.save.
  Операция доступна при разрешённой записи сервера; отдельный режим палитры не нужен.
- Успешная отправка SSE подтверждает присутствие наблюдателя независимо от
  замедления JavaScript-таймера фоновой вкладки. При скрытии вкладки интерес
  снимается немедленным watch. Когда и SSE, и heartbeat прекращаются, lease
  по-прежнему истекает через ~8–9 секунд после последнего подтверждения.
- Краткий разрыв HTTP/SSE восстанавливается до 15 секунд в рамках существующего
  SOX-сеанса; повторный вход на устройство не выполняется. При настоящем закрытии
  SOX либо истечении lease интерфейс показывает причину и требует ручного входа.
  Причины истечения heartbeat/закрытия SOX записываются в журнал сервера.

Версия 0.3.6: при отпускании несовместимого провода причина отказа показывается
прямо на схеме, без молчаливого исчезновения. Типы портов видны в палитре и
подсказках портов. Для кита bclimateMath-8a78be5b: Abs имеет int-вход/выход,
Fabs — float. Выход math::Add2 float соединяется с Fabs; для Abs нужен явный
конвертер float→int. Автоматическое изменение типа или вставка конвертера
не выполняются. Проверено на настоящих манифестах Abs/Fabs в локальном редакторе.

Версия 0.3.4: улучшено соединение портов в React Flow. Область захвата 18 px,
радиус присоединения 26 px, подсветка подходящего порта. Можно протянуть провод
или нажать выход справа, затем вход слева. В черновике связь меняет JSON-проект.
Для онлайн-записи включите «Связи через SOX»: создание/удаление подтверждается
повторным чтением таблицы связей, после этого вызывается App.save. Режим выключен
при каждом подключении; повтор запроса с тем же токеном отклоняется. Проверено
на native SVM, включая независимое чтение и декодирование сохранённого app.sab.

Правый клик на блоке: копировать, вырезать, дублировать, удалить. Правый клик на
поле схемы: вставить в точку клика. Правый клик на проводе: удалить связь.
Ctrl+C/X/V/D, Delete и Undo/Redo поддерживаются в локальном черновике.
Буфер компонентов внутренний для текущей вкладки; копия сохраняет тип, кит,
значения и порты, получает новый ID и имя blkN, внешние провода не копируются.
Онлайн удаление связи доступно в режиме SOX; копирование/вставка компонентов
не отправляет изменения на устройство. Для этих операций откройте черновик.

Версия 0.3.3: опция «Запомнить пароль» в профиле подключения. Введите пароль,
отметьте галку и сохраните профиль. При следующем выборе/обновлении страницы
он используется через ссылку credentialId; пароль не возвращается браузеру.
Защита: Windows DPAPI CurrentUser, привязка к адресу, порту и логину.
Зашифрованные записи лежат в data/credentials, не включаются в релизные архивы
или checkpoints. Расшифровка доступна под текущей учётной записью Windows;
перенос под другую учётную запись требует повторного ввода пароля.
Для замены введите новый пароль и сохраните профиль. Чтобы забыть пароль,
снимите галку и сохраните профиль, либо удалите профиль. Обычный профиль без
пароля работает как раньше. Комментарии о несохранении паролей ниже относятся
к версиям до 0.3.3. Подключение с сохранённым паролем проверено на native SVM.

Версия 0.3.2: вкладка «Палитра», поиск по типу/киту и перетаскивание новых
компонентов в React Flow. В локальном черновике блок ставится в точку отпускания,
поддерживает Undo/Redo и сохраняется в JSON без обращений к устройству.
В онлайн-режиме выберите «Куда добавлять → На устройство через SOX», затем
перетащите тип на схему открытой папки. Создание использует SOX add, точную
схему установленного кита, имя blkN, дефолтные config-значения и meta координат.
Далее вызывается App.save. Неустановленные версии китов доступны только локально.
Режим создания выключен при каждом новом подключении. Повтор одного request token
отклоняется; при неопределённом исходе автоматического повтора нет — перечитайте
устройство. Создание и сохранённый app.sab проверены на локальном native SVM;
на 192.0.2.10 тестовые компоненты не создавались.

Версия 0.3.1: в «Обзоре» полноценное дерево компонентов. Стрелка раскрывает
ветку без смены схемы, нажатие на название папки открывает её содержимое,
выбор компонента открывает родительскую папку и выделяет блок. Есть команды
«Развернуть всё» / «Свернуть всё», поиск с родительскими ветками и управление
клавишами ↑ ↓ ← →, Home, End, Enter. Дерево использует прочитанный снимок,
дополнительных SOX-запросов для раскрытия веток нет.

Версия 0.3.0: раскладка через SOX и библиотека китов.

- Для записи: онлайн-подключение, React Flow, список «Сохранение координат».
  «По кнопке Save» накапливает до 64 перемещений; «Сразу после перемещения»
  записывает при отпускании блока. По умолчанию режим выключен.
- Запись изменяет только старшие два байта meta, сохраняет остальные биты,
  проверяет идентичность схемы/компонента и прежние координаты, читает результат
  обратно. После успешного пакета вызывает `sys::App.save` для сохранения app.sab.
  Протокол не подтверждает успешную запись на диск; UI сообщает об этом отдельно.
  На локальном SVM сохранение проверено независимым декодированием файла app.sab.
  Операция не атомарна для нескольких блоков: при сбое возможен частичный результат,
  автоматического повтора нет. Для повторной записи перечитайте устройство.
- Обычный Start.cmd оставляет запись выключенной. Для работы с записью есть
  Start-With-Writes.cmd (сначала остановить прежний экземпляр через Stop.ps1).
- «Киты»: палитра строится из настоящей схемы подключённого устройства, включая
  унаследованные ID слотов, типы, значения по умолчанию и признаки hidden/summary.
  Манифесты запрашиваются автоматически при отсутствии точной версии в кэше.
  Их можно выгрузить архивом кнопкой «Скачать манифесты устройства».
- Импорт XML, ZIP и .kit до 8 MiB сохраняет манифесты и исходный импортированный
  файл по SHA-256 в data/kit-imports. Запись каталога: data/catalog-parts.json.
  Каталог и манифесты доступны после перезапуска. Зависимые манифесты должны быть
  в библиотеке; текущая схема устройства имеет приоритет над импортом другой версии
  одноимённого кита. Базовые 9 типов остаются в палитре для локальной работы.
- Импорт не устанавливает новый исполняемый кит на контроллер. Там обычно есть
  SCode и архив манифестов, исходный .kit не гарантирован. Новые компоненты палитры
  пока добавляются в локальный JSON-проект; загрузка структуры/SCode ещё не включена.

на устройство. Для получения новых метаданных слотов нужно перечитать устройство.
HTML отдаётся с Cache-Control: no-store; уже открытая вкладка требует обновления.

Версия 0.2.2: координаты читаются из свойства `meta` по формату Ontrol:
`x=(meta>>>24)&255`, `y=(meta>>>16)&255`, отображение на сетке 16 px.
Исходное meta, координаты и родитель сохраняются в JSON проекта. Координаты
относятся к родительской папке, поэтому снимок открывается с содержимого корня.

Профили в разделе «Устройство»: название, адрес, порт и логин сохраняются

## 0.3.8 — виды папок и два места хранения

Во вкладке «Обзор» выберите папку, затем откройте «Виды» и прикрепите SVG. «Открыть экран» показывает его крупно. Для каждой папки хранится отдельный экран; привязка использует путь имён от корня, а не числовые SOX ID. Переименование или перенос папки требует повторного прикрепления экрана. Пока это статические SVG: виджеты, динамические привязки к слотам и анимация не реализованы.

Два места хранения:
- «Сохранить на ПК» — `data/ui-projects/<UUID>.json` относительно каталога sedona-web. При замене предыдущая версия сохраняется в `data/ui-projects/backups`. «Загрузить с ПК» восстанавливает выбранный пакет.
- «Сохранить на устройство» — отдельный файл `mcs-ui.json` через штатный SOX putFile, затем getFile и побайтовое сравнение. Перед отправкой пакет сохраняется на ПК. «Прочитать с устройства» получает пакет и сохраняет локальную копию. Нужны LIVE-соединение и права SOX provisioning, для записи также запуск Start-With-Writes.cmd. Обратное чтение подтверждает переданное содержимое, но не устойчивость flash после отключения питания.

Внутри пакета `mcs-sedona-ui` v1 находятся SVG и пути папок; лимит 512 KiB, до 128 экранов. Фиксированное имя исключает произвольную запись app.sab, кода или файлов по пользовательскому пути. Home здесь означает каталог, в который файловый обработчик устройства разрешает относительные SOX URI; абсолютный путь зависит от платформы. Каталоги на контроллере не создаются. На локальной нативной SVM файл расположен рядом с app.sab; на 192.0.2.10 путь, разрешения и сохранность после перезагрузки пока не проверены. Нет автоматической загрузки/перезаписи пакета при подключении. Запись файла SOX не атомарна: при обрыве копия устройства может оказаться неполной, поэтому локальную версию следует сохранять; автоматического повтора нет.

«Экспортировать пакет» скачивает отдельный mcs-ui.json. Обычный экспорт проекта включает пакет в `graph.ui`, обратное открытие восстанавливает его. Старые проекты без UI по-прежнему открываются. Контрольные точки включают локальные пакеты и их промежуточные версии, но релиз не включает пользовательские данные и пароли. SVG отображается как изолированное изображение; скрипты, обработчики событий, foreignObject и внешние ресурсы не допускаются. Разрешён базовый набор SVG-примитивов, градиентов, символов, масок и текста; SVG со стилями в элементе style или растровыми image требует предварительной подготовки.

Проверки: `SEDONA_UI_TEST=1 python tests/integration.py` (в PowerShell: `$env:SEDONA_UI_TEST='1'` перед запуском). Проверяется запись/чтение через настоящую локальную SVM, независимая проверка файла на диске, неизменность app.sab и kits.scode, локальное хранение, браузерный импорт SVG, полноэкранный просмотр, включение в проект, разные пути папок и отказ от SVG со script. См. evidence/ui-storage.json, ui-folder-binding.json, ui-folder-svg.png.

## 0.4.0 — живые виджеты поверх SVG

Во вкладке «Виды» можно создать пустой экран или использовать ранее прикреплённый SVG. В секции «Добавить виджет» выбираются вид, компонент внутри текущей папки, слот, подпись, единица и точность. Добавлены значение, bool-индикатор и уставка. Для уставок доступны только поддержанные записываемые скалярные типы; для индикаторов — bool. Скрытые конфигурационные параметры доступны для явного выбора, meta и имена секретных полей исключены. Для изменения настроек виджет пока можно удалить и добавить снова; положение меняется непосредственно на экране.

«Открыть экран» показывает SVG с виджетами. Переключатель «Разместить виджеты» разрешает перетаскивание за заголовок; при этом запись уставок заблокирована. Координаты сохраняются в процентах относительно поля экрана. SVG растягивается на это поле, чтобы координаты рисунка и виджетов масштабировались вместе. Размещение фиксируется в документе по отпусканию указателя; для сохранения на диск или контроллер после размещения следует нажать соответствующую кнопку. Фон SVG можно заменять без удаления виджетов. Экран можно открыть и без SVG.

Привязка хранит путь компонента относительно папки, имя слота и ожидаемый тип, не числовой ID компонента. Например folder=app/ahu1, path=sensor, slot=out. Путь «.» означает саму папку. При каждом открытии/изменении графа числовые ID разрешаются заново. Несуществующий или неоднозначный путь, отсутствующий слот и изменение его типа показываются в виджете и блокируют запись. Long/int значения выводятся исходным текстом, без округления через Number; число знаков после запятой применяется к float/double.

При открытом экране HTTP watch передаёт только компоненты его виджетов. Повторные привязки к одному компоненту объединяются, отдельные SOX-сеансы и таймеры опроса для виджетов не создаются. Общая подписка теперь получает CONFIG и RUNTIME, так как уставки и ConstFloat/ConstBool содержат конфигурационные свойства. После закрытия экрана восстанавливается обычный интерес схемы; скрытая вкладка снимает интерес как раньше. Сбор истории и тренды этим изменением не запускаются.

Уставка использует существующие /write/prepare и /write/commit: ввод → «Подготовить» (чтение до, без записи) → «Подтвердить» (проверка неизменности, однократная запись, readback). Автоматического повтора нет. app.sab этой операцией не сохраняется. Запись доступна только при LIVE, разрешённых сервером записях и свежем SSE (до 5 секунд); при выключенном соединении показывается «Снимок», при прерывании потока — соответствующее состояние. Это оценка свежести доставки кэша сервиса, а не отдельный аппаратный quality-бит контроллера. При закрытии экрана подготовленный, но не отправленный план отменяется.

Пакет mcs-sedona-ui v1 расширен необязательным views[].widgets, старые пакеты без widgets открываются. До 64 виджетов на экран, общий предел 512 KiB сохранён. Виджеты включаются в сохранение на ПК, mcs-ui.json на устройстве, экспорт пакета и экспорт всего проекта. Промежуточные версии локальных файлов сохраняются как раньше.

Проверки: node --test tests/view-bindings.test.mjs tests/project.test.mjs; $env:SEDONA_WIDGET_TEST='1'; $env:SEDONA_UI_TEST='1'; python tests/integration.py. Для отдельного тестового сервера предусмотрен SEDONA_TEST_URL, например http://127.0.0.1:8099. На изолированном Java/SVM стенде проверены COV конфигурационных значений, bool-индикатор, три виджета на двух подписках, prepare без записи, подтверждение с независимым SOX readback, перетаскивание, блокировка записи в режиме размещения и OFF, передача пакета с виджетами через устройство и сохранность старого SVG-импорта. В тестовой программе используются probe (ConstFloat) и bool1 (ConstBool), реальные устройства не изменяются. Отчёт: evidence/widgets-native.json; изображение: evidence/live-svg-widgets.png.

## 0.5.0 — отдельные SVG-объекты и библиотека на контроллере

На открытом экране появилась «Библиотека SVG». Базовая палитра подгружается только по открытию: вентилятор вправо, заслонка, нагреватель, фильтр, короткий воздуховод, вход и выход канала. Это 7 ресурсов из kitPxMcs4svg-wb.jar, а не весь каталог из 973 исходных SVG. Свои ресурсы можно добавить файлами Off/On или импортом mcs-svg-library v1. Файлы Off и On должны иметь одинаковый собственный размер. Библиотеку можно экспортировать отдельно.

Объект перетаскивается из палитры на экран или добавляется кнопкой +. Для перемещения включить «Разместить виджеты»; выделить объект, настроить подпись и поворот, затем «Применить привязку SVG». Доступны дублирование/удаление кнопками, Ctrl+D и Delete; при открытом экране эти клавиши не изменяют компоненты скрытой схемы. Режимы:
- Статический: библиотечное изображение Off без зависимости от сети.
- Off / On по bool: относительный путь компонента и имя bool-слота. Вентилятор On содержит штатную SVG-анимацию ротора, корпус не вращается. Она появляется только при свежем true, при Off/Unknown/Fault анимация удаляется из отображаемого изображения.
- Положение 0–1: числовой сигнал выбирает один из пяти вариантов Off / 25 / 50 / 75 / On. Значение вне 0–1 или неизвестный/сменившийся тип даёт Unknown, не зажимается к нормальному положению.
- Отдельная bool-привязка неисправности имеет приоритет. True показывает Fault с красной меткой !, отсутствующие данные дают Unknown с серым символом и ?. При отсутствии специального Fault/Unknown SVG используется статический Off с явной меткой качества. Если нужного нормального варианта изображения нет, нормальное состояние не подменяется — показывается Unknown.

Объекты сохраняют исходные размеры/пропорции, длина канала набирается штатными сегментами. Весь экран теперь вписывается равномерно в область просмотра, включая SVG-фон, объекты и позиции виджетов. Масштаб всего экрана отличается от изменения размеров отдельных объектов. Произвольного редактирования внутренних SVG-групп и непрерывного управления поворотом по числу пока нет.

UI-пакет с библиотекой/объектами получает mcs-sedona-ui v2: library содержит SVG-состояния, objects ссылается на assetId. Один ресурс хранится один раз независимо от количества экземпляров. Вариант «Включить всю библиотеку в пакет» включает всю доступную базовую/импортированную палитру; иначе добавляются только использованные ресурсы. При удалении объекта его ресурс автоматически не удаляется, чтобы не потерять библиотеку. Всё хранится в том же mcs-ui.json на устройстве, отдельного расширения SOX нет. Общий предел 512 KiB, до 64 ресурсов / 128 объектов / 64 числовых виджетов на экран. Базовая библиотека около 144 KiB; произвольный полный каталог из 973 SVG в этот предел не рассчитан. Локальная копия и промежуточные версии сохраняются прежним способом. Старые v1 пакеты читаются, старые редакторы v1 отклоняют v2 вместо молчаливого удаления графики.

Библиотека полученного с устройства пакета самодостаточна: для отрисовки сцен стандартный каталог на ПК не нужен. Повторные экземпляры и обычные виджеты используют общие подписки на компоненты; отдельные SOX-подключения и циклы опроса на объект не создаются. Начальное чтение структуры программы в этом выпуске не менялось. При передаче большого UI-пакета gateway не держит общий монитор: SSE и heartbeat продолжают работать; изменение подписок откладывается до конца передачи, прочие мутации устройства временно запрещены. Отключение устройства остаётся явным и прерывает передачу. На скрытой вкладке интерес снимается как раньше.

Безопасность SVG: isolated img, без JavaScript, событий, внешних ресурсов и foreignObject. Разрешён ограниченный animateTransform: transform/rotate, конечные from/to, период 0.05–120 секунд, repeatCount=indefinite, без href/begin/событий. Это сохраняет штатный ротор библиотеки без поддержки произвольных SMIL-команд.

Пример нового формата: examples/svg-library/mcs-scene.ui.json (отдельный пакет), mcs-scene.sedona.json (проект со снимком), mcs-base-library.json (отдельная библиотека), sources.json (происхождение ресурсов). Папка примера app/sim/cascade. Вентилятор демонстрирует run/overloaded модели, а не физический сигнал вентилятора; заслонка демонстрирует valve.out/stuck. Программа устройства и его существующий пакет не перезаписываются при подготовке примера.

Проверки: node --test tests/svg-objects.test.mjs tests/view-bindings.test.mjs tests/project.test.mjs; SEDONA_SVG_TEST=1 SEDONA_WIDGET_TEST=1 SEDONA_UI_TEST=1 python tests/integration.py (в PowerShell задавать переменные через $env:). Изолированный Java/SVM стенд: реальный HTML5 drag/drop, COV bool, приоритет неисправности, остановка ротора, 5 положений, перетаскивание и дублирование/удаление, импорт собственного SVG, передача полной библиотеки и проверка файла на диске, сохранение LIVE при длительной передаче, старый формат/неразрешённая ссылка отвергаются. Повторный просмотр в новом браузере выполняется с блокировкой загрузки PC-каталога. Старые числовые виджеты и импорт SVG проверяются отдельно. Отчёт evidence/svg-library-native.json, снимок evidence/svg-object-library.png.

Финальные проверки библиотеки выполнены на локальной native SVM; новый пример отдельно проверен офлайн, см. examples/svg-library/acceptance-offline.json.

# Кнопка Вкл/Выкл 0.7.1 и управление примером

Диагностика стенда 10.11.2026: app/sim/cascade — bccSim::SimClock, sessionId=1, run=true; app/sim/session — bccSim::SimSession, sessionId=1, state=1. Демонстрационный SVG-вентилятор привязан к cascade.run. SimSession.advance каждый цикл вызывает setRun(state==1), который перезаписывает run у всех своих SimClock. Текущая анимация показывает работу модели, не подтверждение работы физического двигателя. При диагностике программа и состояние сессии не изменялись.

# Выбор базы выравнивания 0.8.3

В режиме размещения доступны «Границы выделения», «Первый объект» и «Края схемы». Чтобы выровнять виджеты по изображению, сначала выберите SVG, затем Shift+кликом остальные элементы, выберите «Первый объект»; при необходимости фильтр «Только виджеты». Настройки инструмента живут до закрытия экрана; результат сохраняется координатами в пакете, поддерживает отмену/повтор. Проверены геометрия и поведение первого объекта в браузере.

# Стыки и компактный живой пример 0.8.4

Для соединения SVG нужны не «По левому краю» (ставит одинаковый X), а «Стыковать справа/слева». Включите размещение, щёлкните по пустому месту для сброса выделения, выберите неподвижный воздуховод первым, затем Shift+клик по вентилятору и нажмите «Стыковать справа». Объект переместится к правой границе и верхней координате первого, без изменения размера. Для нескольких объектов учитывается порядок выбора. Объекты удерживаются внутри сцены; при нехватке места точная стыковка у края не гарантируется. Точные X/Y в пикселях исходного холста добавлены в инспектор SVG; после изменения нажмите «Применить привязку SVG».

# Перезапуск модели 0.8.5

В заголовке экрана появилась кнопка «Перезапустить модель», если в схеме есть `bccSim::SimSession`. При нескольких сессиях требуется выбор. Подтверждение поясняет, что сбрасываются время и состояние всех принадлежащих сессии SimClock, а не контроллер/программа. Параметры модели не переписываются, App.save не вызывается. График продолжает накапливать точки после сброса.

Сервер разрешает только штатный action `bccSim::SimSession.restart()`, проверяет LIVE-lease, разрешение записи, отсутствие передачи файла/незавершённой записи и актуальность схемы. Уникальный токен потребляется до вызова; повтор запрещён, автоматического повтора нет. Результат проверяется по увеличению generation, state=1, fault=0. При неизвестном результате сначала следует прочитать состояние, не повторять команду вслепую. Не более 64 токенов на SOX-сеанс.

Нативная проверка `tests/restart-model-live.mjs` выполнена один раз на `.184` через отдельный тестовый шлюз 8102: открытие подтверждения ничего не отправило, action вызван один раз, поколение 1→2, работа и отсутствие ошибки подтверждены обратным чтением, повтор токена отклонён. Снимок: `examples/compact-ahu/model-restart-live.png`. Основной пользовательский SOX-сеанс во время теста не разрывался. Для установки новой серверной функции основной веб-шлюз затем перезапускается отдельно; клиент должен переподключиться.
