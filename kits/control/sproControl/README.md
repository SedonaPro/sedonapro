# sproControl

Регулирование для инженерных систем и технологии. Правила — `docs/pro-kits.md`.

| Компонент | Что делает |
|---|---|
| `Pid` | ПИД-регулятор (подробно ниже) |
| `LoopSelect` | выбор min/max из выходов регуляторов для схем ограничения (override) |
| `Sequence4` | секвенция (split range): один запрос → до 4 исполнительных устройств по очереди |
| `Stager` | ступени из запроса: линейно или двоично (1-2-4), задержки, мин. время работы/простоя, `vernier` для модулирующей ступени |
| `ThreePoint` | трёхпозиционный привод без обратной связи: импульсы открыть/закрыть по времени хода, дожим в упор, синхронизация |
| `TimeProp` | ШИМ для ТЭНов (период, мин. импульс и пауза) |
| `SpRamp` | плавный выход на уставку, старт от текущего значения |
| `OnOff` | двухпозиционный регулятор с дифференциалом и мин. временами |

## Pid

- Коэффициенты в инженерных единицах: `kp` — % выхода на единицу ошибки, `ti` и
  `td` — секунды. Из `LP` ядра: `ti = 60 / ki`.
- Обратного действия по умолчанию (нагрев), `direct` — для охлаждения и вытяжки.
- Без насыщения интегратора: на `outMin`/`outMax` и при ограничении скорости
  `outRate` интеграл останавливается там, где выход, и регулятор уходит с
  ограничения сразу, как только меняется знак ошибки.
- Безударно: старт (от `startValue`), возврат из `hand`/`off`/`enable = false`,
  слежение `track`/`trackValue`, смена `kp`, потеря и возврат датчика.
- D — по измерению с фильтром `tdFilter` (скачок уставки не даёт удара).
- `spWeight < 1` смягчает реакцию P на изменение уставки; `deadband` останавливает
  интегрирование вблизи уставки (клапан не «дёргается»).
- Неверный `pv`: выход держится (`onBad = hold`) или уходит в `safeValue`.
- `period` — период расчёта (1 с по умолчанию; 0 — каждый цикл).
- `tiDown` — отдельное время интегрирования на уменьшение выхода (клапан
  калорифера открывается быстро, закрывается медленно); 0 — как `ti`.
- `lowLimit`/`highLimit` — динамические границы выхода по связи (подпор по
  наружной температуре, ограничение в межсезонье); нижняя важнее.
- `gainScale` — множитель `kp` (усиление ближе к опасной зоне), смена без скачка.
- `PidAlgo` — тот же алгоритм без компонента: им пользуются крупные блоки
  (`sproHvac`), держа внутри несколько регуляторов.

### Схема ограничения (override)

Пример: охлаждение приточного воздуха по температуре помещения, но не ниже 16 °C
на притоке. Два `Pid` (оба `direct`), их `out` → `LoopSelect` (`low = true`) →
клапан; `LoopSelect.out` связан с `feedback` обоих регуляторов, у обоих
`useFeedback = true`. Регулятор, которому нужно меньше, ведёт; второй следит за
выходом без насыщения и перехватывает плавно (проверено тестом `PidTest.testOverride`).
При пуске регулятор с `useFeedback` встаёт сразу в установившееся положение
(выход схемы плюс его П-часть): регулятор ограничения, далёкий от предела, не
перехватывает клапан на время, пока догоняет его интеграл.

Скорость, с которой меняется выход, задаёт регулятор, который сейчас ведёт: при
выборе минимума, если обоим нужно больше, ведёт тот, у кого меньше П-часть.
Ограничение, которое должно действовать только у предела (обратка ИТП), удобнее
делать сдвигом уставки — так устроен `sproHeat::HeatingCircuit`.
