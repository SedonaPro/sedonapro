# sproEnergy

Учёт энергии и электроснабжение. Правила — `docs/pro-kits.md`. Счётчики
наследуют `Retained`: с `RetainService` в приложении показания переживают
перезапуск и пропадание питания. Время берётся у `datetime::DateTimeService`.

| Компонент | Что делает |
|---|---|
| `EnergyMeter` | энергия из мощности (кВт) или из показаний счётчика (кВт·ч: Modbus, `PulseCounter.total`); тарифные зоны по времени суток — ночь (T2), пик (T3), остальное — день/полупик (T1); `today`, `yesterday`, `thisMonth`, `lastMonth`; скачок или откат показаний (замена счётчика) не учитывается |
| `HeatMeter` | расчётная тепловая энергия по расходу и температурам подачи и обратки (плотность и энтальпия воды): мощность, кВт·ч, Гкал, объём |
| `PeakDemand` | средняя мощность за интервал 15/30/60 минут по часам (как считает энергосбыт), прогноз на конец интервала, максимум месяца; отключение до 4 нагрузок по очереди при превышении лимита и возврат в обратном порядке |
| `Ats` | АВР: два ввода, ввод и ДГУ или два ввода и ДГУ; разрыв перед включением (все выключатели отключены, пауза, контроль по блок-контактам), возврат на основной ввод с задержкой, пуск ДГУ, прогрев, расхолаживание, неудачный пуск; невключившийся выключатель — переход на следующий источник; неотключившийся — запрет любых переключений; вход `block` (КЗ на шинах) замораживает АВР |

`EnergyMeter` и `HeatMeter` — технический учёт для управления и диагностики, не
коммерческий.

**АВР.** Программная блокировка не заменяет электрическую и механическую
блокировку выключателей: в шкафу АВР она должна быть. Отказы, которые компонент
обрабатывает, проверены тестом на модели выключателей (`EnergyTest.testAts`),
на настоящем шкафу компонент не проверялся.

Связи (как в `examples/energy.xml`):

```
реле напряжения вводов и ДГУ → Ats.ok1/ok2/okG; блок-контакты → fb1/fb2/fbG
Ats.close1/close2/closeG → выключатели, genStart → пуск ДГУ
мощность (кВт) → EnergyMeter.power, PeakDemand.power; PeakDemand.shed1..4 → отключаемые нагрузки
```

Лицензия: Apache 2.0.
