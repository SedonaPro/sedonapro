# sproAhu

Конфигуратор вентустановки. В приложение ставится один компонент `Ahu`, в его
свойствах выбирается, из чего состоит установка. Действие `build` (или первый
старт при `buildOnStart`) собирает внутри блоки `sproHvac`, точки ввода-вывода
платы и все связи между ними.

## Возможности

| Свойство | Варианты |
|---|---|
| `layout` | `supply` — приточная, `supplyExhaust` — приточно-вытяжная |
| `heater` | `none`, `water` (водяной калорифер со всеми защитами), `electric` |
| `valve` | клапан водяного калорифера: `analog` (0–10 В) или `threePoint` (открыть/закрыть) |
| `elStages` | ступени электрокалорифера, 1–4 |
| `recovery` | только для приточно-вытяжной: `none`, `plate`, `rotary`, `glycol` |
| `cooler` | `none`, `water` (клапан), `dx` (2 ступени компрессоров с мин. временами) |
| `fans` | `onOff`, `vfd` (скорости комфорт/эконом), `vfdPressure` (давление в канале) |
| `control` | `supply` — по притоку, `room` — каскад по помещению (у приточно-вытяжной — по вытяжке) |
| `waterSensor` | датчик температуры теплоносителя → компенсация в калорифере |
| `frostThermostat`, `fireInput`, `filterSwitches`, `fanSwitches`, `startSwitch` | какие дискретные входы есть |
| `autoChannels` | брать свободные каналы платы по порядку |

Что получается:

- **Блоки:** `season`, `ctl` (AhuControl), `temp` (SupplyTemp), `heater`, `valve`
  (ThreePoint), `rec`, `dx`, `fanS`/`fanE`.
- **Точки:**
  - аналоговые входы `tOut`, `tSup`, `tRet`, `tWat`, `tRoom`, `tExt`, `tExh`, `pDuct`;
  - дискретные входы `diStart`, `diFire`, `diFrost`, `diOverH`, `diFltS`/`E`, `diFbS`/`E`;
  - дискретные выходы `doDamp`, `doFanS`/`E`, `doPump`, `doOpen`/`doClose`, `doH1..4`, `doDx1/2`;
  - аналоговые выходы `aoValve`, `aoFanS`/`E`, `aoRec`, `aoCool`.
- **Аварии:** `alFbS`/`E` (вентилятор не подтвердил работу → останов
  установки через `faults`), `alFltS`/`E` (фильтры).
- **Каналы платы:**
  - `ioList` — «AI1 tOut, AI2 tSup, …»;
  - `missing` — сколько точек не получили канал;
  - канал, заданный вручную, сохраняется при пересборке.

## Пересборка

После изменения свойств снова `build`:

- блоки того же типа остаются со всеми уставками и настройками;
- новые добавляются;
- лишние удаляются.

Свойства, которые прямо следуют из вариантов (тип рекуператора, режим
вентилятора, каскад, доля рекуператора), выставляются заново. Всё внутри `Ahu`
принадлежит конфигуратору: свою логику ставьте рядом. Связи в его блоки
конфигуратор заменяет своими.

Запуск по расписанию или от диспетчера: связь в `Ahu.request` (или
`startSwitch` — дискретный вход). Ручные режимы — `ctl.mode` (`auto`, `on`, `off`).

## Виджет «Установка»

Kit несёт виджет `ui/ahu.widget.json` (формат — `docs/widgets.md`):

- **сторона «Настройка»** — схема установки; щелчок по элементу открывает его
  опции, отсутствующие части показаны бледно, кнопка «Собрать» с подтверждением;
- **сторона «Работа»** — та же схема с живыми значениями: заслонки, вентиляторы,
  клапан, насос, аварии, температуры, режим, уставка.

Значки — свои (`ui/svg`), тексты переведены в `ui/texts.ru.json`. Редактор берёт
виджет с контроллера (`m:ui.zip`) или из SDK (`build/home/ui/sproAhu`).

## Пример

```sh
./spro build sim --pack hvac --board sim-large --example ahu && ./spro run sim --erase
```

Панель `http://127.0.0.1:8090`:

- **входы:** AI1 — улица, AI2 — приток, AI3 — обратка; DI1 — пуск, DI5 — реле перепада вентилятора;
- **выходы:** DO1 — заслонки, DO2 — вентилятор, DO3 — насос; AO1 — клапан, AO2 — скорость.

Включите DI1: прогрев, через минуту заслонки, затем вентилятор; поставьте DI5
(вентилятор подтвердил работу). AI3 ниже 8 °C — авария «мороз».
