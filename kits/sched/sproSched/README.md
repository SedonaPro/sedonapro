# sproSched

Расписания: праздники, недельное расписание, оптимальный пуск. Правила —
`docs/pro-kits.md`. Время берётся у `datetime::DateTimeService` приложения
(на Linux он в приложении по умолчанию, на ESP32 его добавляет фрагмент
`datetime`). Без часов компоненты ставят `status = inputBad` и держат выходы.

| Компонент | Что делает |
|---|---|
| `Calendar` | праздники и особые дни: `01-01`, `01-01..01-08`, `12-30..01-02` (через Новый год) — каждый год; `2026-05-11`, `2026-12-28..2027-01-03` — конкретные даты. Выходы `today`, `tomorrow`, `yesterday` |
| `WeekSchedule` | недельное расписание: программа на каждый день (`mon`…`sun`) и программа особых дней `hol`; до 6 периодов в сутки, `07:00-12:00, 13:00-18:00`, период через полночь `22:00-06:00`, свой уровень периода `06:30-08:00=21.5`. Выходы `occupied`, `out`, `nextChange` (минут до переключения), `nextOccupied`; продление кнопкой (`request`, `extend`), ручной режим |
| `OptimumStart` | ранний пуск: включает установку заранее, чтобы к началу занятости помещение прогрелось; упреждение растёт с недогревом помещения и холодом на улице, с `adapt` подстраивается по каждому пуску |

Связи (как в `examples/ahu-schedule.xml`):

```
Calendar.today/tomorrow/yesterday → WeekSchedule.holiday/holidayTomorrow/holidayYesterday
WeekSchedule.occupied/nextOccupied/nextChange → OptimumStart
OptimumStart.run → Ahu.request (или запрос насосов, котла …)
```

Ошибка в записи календаря или в периоде программы не останавливает остальное:
неверная запись пропускается, `status = config`, номер — в `badEntry` /
`badProgram`. `nextChange` смотрит до конца завтрашнего дня (послезавтра
считается обычным днём).

На ESP32 часы верны только после установки времени, синхронизации по сети
(SNTP) в прошивке пока нет; часовой пояс там — UTC.

Лицензия: Apache 2.0.
