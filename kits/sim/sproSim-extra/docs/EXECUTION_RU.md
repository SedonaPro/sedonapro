# Контракт исполнения sproSim 0.1

## Часы

Все длительности — секунды. `dt` — фиксированный шаг интегрирования 0.0001…60, `rate` — отношение модельных секунд к реальным (0…10000).
По монотонным `Sys.ticks()` контекст накапливает elapsed×rate и исполняет целые шаги dt.
Ускорение увеличивает число шагов; численный шаг от него не меняется.
`maxSteps` 1…1000 ограничивает число шагов одного контекста за цикл VM. Неисполненное время остаётся в `backlog`.
`overloaded=true` означает, что накопился хотя бы один полный шаг. Это предупреждение о недостаточной производительности, а не потеря времени.
Контексты делят один поток и процессор. Ограничение шагов не обеспечивает жёсткий real-time SLA.

`run=false` приостанавливает часы, сохраняя остаток времени. `step` выполняет один шаг только при паузе.
`reset` ставит на паузу, обнуляет часы, счётчик и backlog, сбрасывает состояния моделей к initial.
Сброс не меняет входы, уставки и переключатели неисправностей: учебный сценарий должен выставлять их явно.
`autoRun` — сохраняемая конфигурация запуска. Текущее `run` — оперативное состояние.
После первого шага изменение dt запрещено до reset. Изменение rate допускается без сброса.
Остальную конфигурацию моделей меняйте на паузе с последующим reset. Оперативные входы можно менять при run.

## Топология и порядок

SimClock содержит только непосредственных потомков SimBlock, не более 128.
Вложенные папки, часы и обычные компоненты sys/control/math внутри него отклоняются.
`allowChildExecute=false` предотвращает повторное исполнение приложением. Вызов обычного execute у SimBlock ничего не делает.
Размещённый вне SimClock блок моделирования сам не рассчитывается.

За каждый шаг контекст обходит фазы 0…7; в одной фазе действует порядок соседей в дереве Sedona.
Перед tick каждого блока штатный Link.propagate обновляет его входы.
Рекомендуемые фазы: источники 0, регулятор 1, привод 2, объект 3, датчик 4, логирование 7.
В простом примере без привода объект имеет фазу 2, датчик 3.
Обратная связь от более поздней фазы читается на следующем шаге. Алгебраические петли не решаются.
Последовательные блоки одной фазы дают результат, зависящий от их порядка: задавайте разные фазы для однозначных цепочек.

Все входящие связи блоков должны идти от других блоков того же контекста и соединять свойства одинакового типа.
Каждый класс явно объявляет разрешённые входы через acceptsInput. Запись связью в config, out или внутреннее состояние отклоняется.
Связи между контекстами не разрешены. Чтение результатов внешним наблюдателем возможно, но наблюдатель работает по реальному циклу VM.

Перед шагами проверяется весь контекст. fault: 0=OK, 1=параметры часов/смена dt/некорректный elapsed, 2=топология или связь, 3=конфигурация блока.
При ошибке шаги не исполняются, модельное время не меняется. Исправление конфигурации допускает дальнейшую валидацию; обычно нужен reset.
Валидация конфигурации не доказывает физическую осмысленность коэффициентов.

## Численные модели

FirstOrder и Sensor используют backward Euler: alpha=dt/(tau+dt), y=(1-alpha)·y_old+alpha·target.
При tau=0 выход равен target. Метод устойчив для tau≥0, но точность требует dt существенно меньше характерного времени.
Рекомендуется проверка сходимости: уменьшить dt вдвое и сравнить траектории на одном модельном времени.

SampleDelay хранит 256 float (1024 байта плюс поля). Задержка samples×dt; при reset вся история заполняется initial.
Параметр samples меняется только с reset. При недопустимом входе история и её позиция удерживаются.

Valve: out∈[0,1], скорость не больше 1/travel за секунду; travel=0 даёт мгновенный привод.
Сигнал stuck удерживает позицию. Модель не включает гистерезис, расходную характеристику и перепад давления.
Sensor: frozen удерживает последнее значение и выставляет good=false. Смещение имеет те же единицы, что измерение.

SimPi: p=kp·(sp-pv), ΔI=p·dt/ti, out=clamp(p+I+feedforward,lo,hi).
Интегратор обновляется, если кандидат внутри ограничений либо приращение направлено от насыщения.
В manual интегратор отслеживает manualOut−p−feedforward. Это обеспечивает плавный переход при неизменной ошибке и feedforward.
Начальный integral=initial; это не автоматическое слежение за начальным p. Для старта под ненулевой ошибкой используйте ручной режим перед auto.
Знаки: положительный kp для нагрева, отрицательный для охлаждения при принятой ошибке sp−pv.

FirstOrder, Sensor, SampleDelay и SimPi имеют good. При неконечном входе удерживают предыдущее состояние, good=false.
good необходимо учитывать при построении сценариев; SimClock не является защитным автоматом и не переводит весь контур в безопасное состояние при good=false.
Valve удерживает out при неконечном command; отдельного сигнала качества у него в 0.1 нет.

## Добавление компонентов

Наследуйте SimBlock; определите config-параметры, runtime-входы, readonly-выходы.
Переопределите valid, acceptsInput, resetState, tick(dt,time). Всегда вызывайте super.valid().
Никаких Sys.ticks, sleep, сетевых операций и изменяемого общего static-состояния в tick.
Не полагайтесь на реальный scanPeriod. resetState обязан полностью восстанавливать динамическую память блока.
Каждый новый класс должен иметь тесты единиц, краёв параметров, повторного reset и работы с несколькими контекстами.
