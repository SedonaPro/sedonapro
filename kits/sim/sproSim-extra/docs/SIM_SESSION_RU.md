# SimSession — контракт эксперимента sproSim 0.3.0

Сессия — компонент Sedona, не служба MCS. В одной VM допускается несколько независимых сессий и прежние независимые SimClock.

## Подключение

Добавьте SimSession, задайте sessionId > 0. У входящих SimClock задайте тот же sessionId и одинаковый dt. Расположение в дереве не влияет на принадлежность. Сессия с таким номером должна быть единственной; от 1 до 16 часов. sessionId=0 у часов сохраняет прежний независимый режим.

Управляемые часы сами не рассчитываются: сессия использует один накопитель времени и обходит все часы на каждом фиксированном шаге. Скорость rate и бюджет maxSteps задаются на сессии. dt часов должен совпадать с dt сессии. Блоки разных часов не связываются напрямую: проверка топологии запрещает такие связи.

## Команды

| Action | Результат |
|---|---|
| pause | Остановить с сохранением времени и состояния |
| reset | Сбросить все часы и модели, оставить на паузе |
| restart | Сбросить и запустить |
| step | Один общий шаг, только из паузы |
| resume | Продолжить с текущего состояния |

Команда принимается в очередь busy и исполняется в следующем execute сессии. Вся предварительная проверка, остановка, сброс и запуск часов одной сессии происходят в одном вызове VM, без сетевых команд между часами. Первое продвижение времени происходит на следующем цикле. Команда при busy отклоняется; rejected увеличивается. commandCount увеличивается при обработке команды. Параллельные управляющие клиенты должны проверять busy и результат. MCS выполняет управление последовательно и ожидает подтверждение VM; неопределённый результат не повторяется автоматически.

state: 0 пауза, 1 расчёт, 2 ошибка. fault: 1 настройки сессии, 2 состав/дублирование владельца, 3 настройки часов или моделей, 4 несогласованное состояние часов. Ошибка останавливает все часы сессии и сохраняется до reset/restart. Исправление настройки само по себе расчёт не возобновляет. Если предварительная проверка сброса не пройдена, состояния моделей не сбрасываются.

## Воспроизводимость

reset/restart обнуляет time, steps, backlog, overloaded и внутренние состояния моделей через SimBlock.resetState(). Начальные выходы определяются initial/before соответствующей модели. Параметры, текущие входы и вручную включённые неисправности сохраняются. Для полностью одинакового повторного опыта нужно восстановить одинаковые параметры, входы и неисправности; сценарные StepSignal/BoolStep воспроизводятся от общего time.

generation увеличивается при успешном reset/restart и записывается всем часам. Это счётчик внутри текущего процесса VM, не долговременный номер опыта. При смене dt остановите сессию, измените dt у сессии и всех часов, затем выполните reset/restart.

Общий restart нескольких разных сессий остаётся последовательностью команд: атомарность относится к одной сессии. Не меняйте run и не вызывайте reset/step напрямую у управляемых часов через сторонний SOX-клиент: управляйте сессией. MCS автоматически направляет команды управляемых часов их сессии.

## Установленный стенд

192.0.2.10:11876, /sim/session, sessionId=1, dt=0.25 с, rate=10. В сессию входят /sim/compare/plain, /sim/compare/assist, /sim/cascade. Текущие настройки и идентификаторы прежних 55 компонентов сохранены; добавлена только сессия id=81. Пример для повторного использования: examples/session-compare.sax.

Проверки: native VM Windows — 8380 assert success, Linux amd64 — 8379, ошибок 0. Native SOX проверяет pause/reset/step/restart/resume, равенство time/steps/generation всех трёх часов и сохранение параметров StepSignal на копии и действующем приложении. MCS проверяется отдельно через FOX.
