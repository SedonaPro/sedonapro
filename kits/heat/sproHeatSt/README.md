# sproHeatSt

Конфигуратор индивидуального теплового пункта (ИТП). Как `sproAhu::Ahu` и
`sproPumpSt::PumpStation`: выбираете состав в свойствах и вызываете `build` —
компонент `HeatStation` наполняет себя блоками `sproHeat` и `sproEquip`,
точками входов-выходов платы и связями.

```
outT → curve1 (график) → circ1 (подача, обратка, мороз) → valve1
                         circ1.pump → lead1 (основной/резервный) → p1a, p1b → do1a, do1b
dhwT → dhw (ожог, дезинфекция, приоритет) → dhwV, dhwP
press → makeup → fill;   все аварии → alarms (AlarmSum) → alarm (DO)
```

| Опция | Что даёт |
|---|---|
| `circuits` | 0–2 контура отопления; у каждого свой график, клапан, датчик подачи, насосы (второй — вентиляция, другое здание) |
| `pumps` | `single` — один насос на контур, `twin` — сдвоенные, основной/резервный с ротацией по наработке (`LeadLag`) |
| `faultInputs` | вход аварии на каждый насос |
| `flowSwitch` | реле перепада давления на контур подтверждает циркуляцию; без него — работающий насос |
| `returnSensor` | датчик обратки на контур: ограничение обратки по графику, защита от замерзания по воде |
| `roomSensor` | датчик в помещении: коррекция графика контура 1 |
| `dhw`, `dhwCirc`, `dhwPriority` | ГВС, её циркуляционный насос, приоритет ГВС над отоплением (ограничивает клапаны отопления) |
| `makeUp` | подпитка по давлению в контуре (`MakeUp`) |
| `alarmOutput` | DO общей аварии: аварии контуров, насосов, ГВС, подпитки |

Входы самого `HeatStation`:

- `request` — разрешение отопления и ГВС (диспетчерская, сезон);
- `setback` — ночное снижение графиков (свяжите расписание через `Not`);
- `disinfect` — фронт запускает дезинфекцию ГВС (недельное расписание).

Защита от замерзания работает и без `request`. Насосам при создании задаются
прокрутка раз в неделю на 30 с (летом не закисают), задержка пуска 2 с,
пауза 5 с.

Повторная сборка сохраняет блоки того же типа с их настройками (наработка
насосов, сдвиг графика, уставки), ненужные части удаляются вместе со связями.
Каналы платы берутся по порядку (`autoChannels`), что куда попало — в
`ioList`. Блоки внутри принадлежат конфигуратору: свою логику ставьте рядом.

Виджет `heat` — мнемосхема ИТП для веб-редактора и Sedona Studio: на стороне
«Настройка» состав и «Собрать…», на стороне «Работа» клапаны, температуры,
насосы с наработкой, подпитка, сдвиг графика, уставка ГВС и режимы.

Пример: `examples/heat-station.xml` (`./spro build sim --pack heat --board sim-large --example heat-station`).
