# Виджеты в составе kit

Kit может принести с собой виджеты — готовые мнемосхемы своих компонентов.
Примеры — виджеты конфигураторов: «Установка» для `sproAhu::Ahu`, «Насосная
станция» для `sproPumpSt::PumpStation` и «Тепловой пункт» для
`sproHeatSt::HeatStation`:

- на стороне настройки — схема, на которой выбирается состав установки, и кнопка «Собрать»;
- на стороне работы — та же схема с живыми значениями.

Редакторы (веб-редактор, Sedona Studio) берут виджеты с контроллера вместе с
описаниями kits или из SDK.

## Где лежат

```
kits/<домен>/<kit>/
  ui/
    <id>.widget.json     шаблон виджета (формат ниже)
    svg/*.svg            значки виджета
    texts.<язык>.json    переводы: { "English text": "перевод" }
```

Тип компонента указывает на свой виджет фасетом:

```
@widget="ahu"
class Ahu extends Component
```

Фасет попадает в манифест kit, по нему редактор узнаёт, что у компонента есть
виджет. Сам шаблон в манифест не входит. Правка картинки не меняет контрольную
сумму kit, приложения на контроллерах остаются совместимыми.

## Доставка

`./spro build` собирает `ui/` всех kits образа в `manifests/ui.zip`:

```
index.json                       {"format": "sedonapro-ui/1", "kits": {kit: {version, checksum, widgets: [...]}}}
<kit>/<id>.widget.json
<kit>/svg/...
<kit>/texts.ru.json
```

- **С контроллера** редактор читает архив по SOX как `m:ui.zip` (рядом с
  `m:m.zip`) и кэширует его по хешу.
- **Без контроллера** те же файлы лежат в SDK: `build/home/ui/<kit>/`.
- С `--manifests none` архив не кладётся.

## Формат шаблона

```json
{
  "format": "sedonapro-widget/1",
  "id": "ahu",
  "type": "sproAhu::Ahu",
  "title": "Air handling unit",
  "size": [1000, 480],
  "parts":   { "tSup": ["sproHal::AnalogInput"], "heater": ["sproHvac::WaterHeater", "sproHvac::ElectricHeater"] },
  "symbols": { "fan": { "off": "svg/fan-off.svg", "on": "svg/fan-on.svg", "fault": "svg/fan-fault.svg" } },
  "options": [ { "slot": "heater", "label": "Heater" } ],
  "elements": [
    { "id": "fanS", "symbol": "fan", "x": 760, "y": 150, "w": 120, "h": 90,
      "when": "true", "state": "doFanS.in", "fault": "alFbS.alarm",
      "label": "Supply fan", "configure": ["fans"],
      "values": [ { "bind": "fanS.out", "unit": "%", "decimals": 0, "dx": 0, "dy": 100, "when": "fans != 'onOff'" } ] }
  ],
  "texts":    [ { "text": "Outdoor", "x": 20, "y": 120 } ],
  "controls": [ { "kind": "mode", "bind": "ctl.mode", "label": "Mode", "x": 20, "y": 420 } ],
  "info":     [ { "bind": "ioList", "label": "I/O" } ],
  "actions":  [ { "id": "build", "invoke": "build", "label": "Build", "confirm": "Rebuild the unit?" } ]
}
```

| Поле | Смысл |
|---|---|
| `type` | компонент, на который ставится виджет (`kit::Type`) |
| `parts` | дети компонента, к которым есть привязки: имя → допустимые типы |
| `symbols` | значки: состояние (`off`, `on`, `fault`) → SVG в `ui/` |
| `options` | настройки самого компонента для стороны «Настройка» (должны быть `@config`); `when` — показывать опцию только при условии (ступени электрокалорифера — только при электрическом). Скрытая опция сохраняет своё значение |
| `elements` | элементы схемы. `state` — bool (вкл/выкл) или число (больше 0 — `on`); `fault` — bool, рисуется как `fault`; `configure` — какие `options` меняются щелчком по элементу; `values` — подписи со значениями рядом; `ghost: true` — на стороне «Настройка» скрытый условием `when` элемент показывается бледным, щелчок по нему открывает его `configure` (так добавляют охладитель, рекуператор) |
| `texts` | постоянные подписи |
| `controls` | `mode` (байт с `range`), `setpoint` (число), `toggle` (bool), `status` (только чтение). Записывать можно только `@config` слоты |
| `info` | значения для стороны «Настройка» (список входов-выходов, предупреждения) |
| `actions` | действия компонента. `confirm` обязателен у всех, что меняют состав или запускают оборудование |

**Привязки.** `слот` — слот самого компонента, `часть.слот` — слот ребёнка из
`parts`. Ничего вне своего компонента виджет не видит и не меняет.

**Условия `when`.** Это `слот оп значение`, соединённые `&&` и `||` (`&&`
сильнее). Слоты — только слоты самого компонента. `оп` — `==`, `!=`, `<`, `>`,
`<=`, `>=`. Значение — имя из `range` в кавычках (`'water'`), число, `true` или
`false`. Пустое или `true` — элемент виден всегда.

**Координаты.** Всё — в единицах поля `size`, редактор масштабирует картинку
целиком.

- Элемент — прямоугольник `x`, `y`, `w`, `h`; значок вписывается в него с
  сохранением пропорций или растягивается, если в SVG указано
  `preserveAspectRatio="none"`.
- Подпись значения (`values`) центрируется по середине элемента со сдвигом `dx`,
  её верх — на `y + dy` элемента.
- Постоянная подпись (`texts`) и элемент управления (`controls`) — левый верхний
  угол в `x`, `y`.

**Тексты.** В шаблоне — по-английски, переводы — в `texts.<язык>.json`, в том
числе имена из `range` (`"supplyExhaust": "приточно-вытяжная"`): редактор
показывает их вместо чисел.

## Безопасность

Виджет приходит с контроллера, то есть из недоверенного источника. Поэтому:

- **Только данные.** Ни скриптов, ни выражений сложнее условий выше.
- **Простой SVG.** Значки рисуют оба редактора: веб — как SVG, Sedona Studio —
  фигурами JavaFX, без браузера внутри. Поэтому разрешён только набор, который
  оба понимают одинаково, всё остальное `ui check` отклоняет:

  | Элемент | Атрибуты |
  |---|---|
  | `svg` | `viewBox` (обязателен), `width`, `height`, `preserveAspectRatio` (`none` — растянуть, или `xMidYMid meet` по умолчанию) |
  | `g`, `title`, `desc` | — |
  | `path` | `d` |
  | `rect` | `x`, `y`, `width`, `height`, `rx`, `ry` |
  | `circle`, `ellipse` | `cx`, `cy`, `r` / `rx`, `ry` |
  | `line` | `x1`, `y1`, `x2`, `y2` |
  | `polyline`, `polygon` | `points` |
  | `text` | `x`, `y`, `font-size`, `font-family`, `font-weight`, `text-anchor` |
  | `animateTransform` | только вращение: `attributeName="transform" type="rotate"`, `from`, `to`, `dur`, `repeatCount` |

  У всех: `id`, `fill`, `stroke`, `stroke-width`, `opacity`, `fill-opacity`,
  `stroke-opacity`, `stroke-linecap`, `stroke-linejoin`, `stroke-dasharray`,
  `transform` (`translate`, `rotate`, `scale`, `matrix`). Цвета — `#rgb`,
  `#rrggbb`, `none` или простое имя (`black`, `white`, `red`, ...). Нет `style`,
  CSS, градиентов, `<use>`, `<image>`, скриптов и ссылок. До 64 КБ на файл.
- **Белый список действий.** Записываются только `options` и `controls`,
  вызываются только `actions`, и всё это — у своего компонента и его детей.
- **Сверка с манифестом.** Редактор сверяет привязки с манифестом kit с
  контроллера. При расхождении виджет не показывается, остаётся обычный список
  свойств.

## Проверка

```sh
./spro ui check
```

Проверяется:

- формат и обязательные поля;
- что каждая привязка указывает на существующий слот (с учётом наследования), а
  `options` и записываемые `controls` — на `@config`;
- что `actions` — действия типа, а условия ссылаются на существующие слоты и имена
  из `range`;
- что SVG укладываются в простой набор выше, файлы на месте;
- что тип в манифесте указывает на этот виджет (`@widget`).

Проверка запускается в CI.

## В редакторах

**Sedona Studio.** У блока, тип которого указывает на виджет, в инспекторе есть
кнопка «Открыть виджет…». Опции меняют черновик проекта (отмена — Ctrl+Z),
элементы управления пишутся через «Применить», действие («Собрать…») —
после подтверждения со списком изменений: сначала применяется черновик,
затем действие вызывается на контроллере, затем устройство перечитывается.
Без контроллера виджет берётся из SDK.

**Веб-редактор** (`editor/`). В режиме LIVE у такого компонента на вкладке
«Сигналы» есть кнопка «Открыть виджет». Опции выбираются заранее; «Собрать…»
показывает, какие опции запишутся, и после подтверждения сервер записывает их
с проверкой обратным чтением, вызывает действие и перечитывает дерево.
Элементы управления пишутся по одному, с тем же подтверждением, что и обычная
запись параметра. Запись и действия работают, только если сервер запущен с `--writes`.

```sh
./spro build linux              # SDK: sedona.jar, манифесты, виджеты
./spro editor build             # Node 20.19+ (SPRO_NODE), JDK 17+ (JAVA_HOME)
./spro editor run --writes      # http://127.0.0.1:8098, только loopback; без --writes только чтение
```

Проверки: `./spro editor test` — модульные тесты в Node и сквозная проверка на
этом ПК (ВМ с `Ahu`, сервер на тестовом порту, API и браузер; браузер — системный Chrome,
`SEDONA_TEST_BROWSER`; без него проверяется только API).
